# tpt-aero-cli

The `tpt-aero` command: aerodynamics and flight mechanics from a TOML case file,
with no Rust required. It drives the same solvers as the library, so a number
from the command line is a number from `tpt-aero-vlm` or
`tpt-aero-stability`.

## Install

From a checkout of this repository:

```text
cargo install --path crates/tpt-aero-cli
```

The tool is not yet published to crates.io. The `tpt-math` sibling checkout is
needed to build, as for the rest of the workspace.

## Commands

```text
tpt-aero template wing -o wing.toml              # a commented starting case file
tpt-aero wing wing.toml -o polar.csv             # alpha sweep to CSV
tpt-aero derivatives wing.toml --alpha 4         # stability derivatives
tpt-aero derivatives wing.toml --alpha 4 --json  # the same, as JSON
tpt-aero vtk wing.toml --alpha 5 -o lattice.vtk  # lattice with circulation, for ParaView
tpt-aero rotor rotor.toml --json                 # one BEMT operating point
tpt-aero trim aircraft.toml --speed 50           # level trim
tpt-aero trim aircraft.toml --speed 50 --bank 20 # coordinated turn trim
tpt-aero isa 0 5000 11000                        # standard atmosphere, as CSV
tpt-aero --help                                  # every command, with its flags
```

| Command | Input | Output |
|---|---|---|
| `template` | `wing`, `rotor` or `aircraft` | A commented TOML case file. |
| `wing` | Wing case | CSV: `alpha_deg,cl,cdi,cm,cl_roll,cn,lift_n`. |
| `derivatives` | Wing or aircraft case, `--alpha` | Derivatives in stability axes; `--json` for JSON. |
| `vtk` | Wing case, `--alpha` | Legacy ASCII VTK. |
| `rotor` | Rotor case | One BEMT operating point; `--json` for JSON. |
| `trim` | Aircraft case, `--speed` (m/s), `--altitude` (m, ISA), `--bank` (deg, below 90) | Level trim, or a coordinated turn with `--bank`; `--json` for JSON. |
| `isa` | One or more altitudes in metres | CSV: `altitude_m,temperature_k,pressure_pa,density,speed_of_sound`. |

Every command accepts `-o` / `--out FILE` to write to a file instead of
standard output.

## Case files

`template` writes a complete, commented case file for each kind. Edit it
rather than writing one from scratch. Unknown or misspelled keys are rejected,
so a typo in a parameter name fails early rather than silently using a default.

```text
tpt-aero template wing     -o wing.toml
tpt-aero template rotor    -o rotor.toml
tpt-aero template aircraft -o aircraft.toml
```

The `wing` columns `cl_roll` and `cn` are body-axis. `derivatives` reports
stability-axis values, so the two will not match in sign or magnitude when
alpha is non-zero. See [docs/CONVENTIONS.md](https://github.com/tpt-solutions/tpt-aero/blob/master/docs/CONVENTIONS.md).

## Examples

The `examples/` folder holds one case file of each kind, generated by
`template`, so you can run every command without writing a file first:

```text
tpt-aero wing examples/wing.toml --out polar.csv
tpt-aero derivatives examples/wing.toml --alpha 4 --json
tpt-aero rotor examples/rotor.toml
tpt-aero trim examples/aircraft.toml --speed 50
tpt-aero trim examples/aircraft.toml --speed 50 --bank 20
tpt-aero isa 0 5000 11000
```

Sample output of `derivatives` on the wing template, at 4 degrees:

```text
derivative,value
cl_alpha,4.927502
cm_alpha,0.025382
...
```

The CLI always takes moments about the quarter chord, the default reference
(`ReferenceGeometry::from_planform`), and no case-file key changes it. A rectangular
wing's aerodynamic centre sits near the quarter chord, so `cm_alpha` is close to
zero here, and its small positive sign is a finite-aspect-ratio effect. For a
stability study about the centre of gravity, use the library and
`VlmModel::with_reference`.

## Limits

These bound the work a single command will do, so a mistyped case cannot
exhaust memory or time:

* ISA: 0 to 84 852 m geopotential (the standard's 86 km geometric ceiling).
* A wing sweep is capped at 10 000 points.
* Each mesh count is capped at 500.
* A surface is capped at 2 500 panels. The dense AIC matrix grows with the
  square of the panel count.

## Output and scripting

* `--json` output is stable JSON suitable for scripts. Floats round-trip exactly
  because the CLI enables `serde_json`'s `float_roundtrip` feature.
* Results go to standard output unless `-o` is given. Errors go to standard
  error.
